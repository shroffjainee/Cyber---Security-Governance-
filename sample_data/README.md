# Sample data

## `synthetic/` — SYNTHETIC fixtures (not real assessments, not real scans)
Generated by `evaluation/synthetic.py` for testing and demonstration.

| File | Content |
|---|---|
| `evidence_compliant.json` | fully compliant Ubuntu evidence document (`data_origin: SYNTHETIC`) |
| `evidence_root_login_violation.json` | same, one day later, `PermitRootLogin yes` |
| `evidence_collector_error.json` | UPD-001 collector failure |
| `greenbone_report_synthetic.xml` | file shaped like a Greenbone XML report; findings and CVE assignments are invented |
| `greenbone_results_synthetic.csv` | same findings in the Greenbone "CSV Results" column layout |

Try: `python cli.py evaluate --evidence sample_data/synthetic/evidence_root_login_violation.json`.
Import with `--synthetic` so the scan is labelled SYNTHETIC.

## `host_evidence_sandbox_container.json` — real collection, but NOT your target VM
A genuine read-only collection from the Ubuntu 24.04 build container used to develop this project
(no OpenSSH, no UFW, systemd not PID 1). It shows how unavailable evidence becomes UNKNOWN or a recorded
limitation. Do not cite it as an assessment of your lab VM.
