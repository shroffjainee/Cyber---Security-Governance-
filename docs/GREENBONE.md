# Greenbone Community Edition / OpenVAS integration

Only scan systems you own or are explicitly authorised to test. The framework itself never scans; it
imports reports you exported.

## 1. Install Greenbone (separate VM recommended)
Use the official **Greenbone Community Containers** guide (greenbone.github.io/docs → "Greenbone
Community Containers"). In outline: install Docker Engine and the compose plugin, download the
`docker-compose.yml` published in that guide, `docker compose -p greenbone-community-edition pull`,
then `... up -d`. Set the admin password as the guide shows, and wait for the feed synchronisation to
finish (can take an hour or more on first start; scans before that produce incomplete results).
Resources: roughly 2 CPU / 4 GB RAM / 20 GB disk minimum, 4 CPU / 8 GB / 60 GB recommended — check the
current guide. Follow the guide's exact commands for your version rather than these notes.

## 2. Authorised scan of the Ubuntu test VM
In the web UI (Greenbone Security Assistant):
1. *Configuration → Targets → New*: host = the lab VM IP (e.g. 192.168.56.10), port list
   "All IANA assigned TCP". Optionally add SSH credentials for authenticated (local security check)
   scanning — gives far more package-level CVEs.
2. *Scans → Tasks → New*: target above, scan config "Full and fast". Start.
3. Record the date/time, scanner version and that the target is your own lab VM (for the dissertation).

## 3. Export
*Scans → Reports* → open the report → download → choose report format **XML** (preferred: contains
report id, scan start/end, NVT OIDs, CVSS, CVE refs, QoD) or **CSV Results**. Apply "no filter / all
results" so low-severity and all hosts are included as desired.

## 4. Import
```bash
python cli.py import-greenbone --asset-id ubuntu-vm-01 --file report-ubuntu.xml
```
Output reports findings imported, duplicates merged, findings skipped (other hosts / no NVT),
missing CVSS, warnings; then the asset is re-scored.

## What the importer does
| Concern | Handling |
|---|---|
| Formats | Greenbone XML report (GVM ≥ 11 `<severities>`/`<refs>`, legacy `<cvss_base>`/`<cve>`), CSV Results |
| Safety | `defusedxml` (DTD/entities forbidden), 100 MB cap, no network |
| Fields | result id, host, port, NVT OID & name, CVE list, CVSS score & vector, threat label, QoD, description, solution, scan start/end, report id, scanner version |
| Duplicates within a report | same (NVT OID, host, port) merged: union of CVEs, max CVSS |
| Repeated imports | same file SHA-256 or same report id for the asset → refused |
| Repeated scans | each scan stored; scoring uses only the latest scan |
| Missing CVE/CVSS | stored as `[]` / NULL; scoring flags estimates |
| Severity −1/−2/−3 | stored as FALSE_POSITIVE / DEBUG / ERROR, excluded from risk |
| Stale data | age computed from scan end (fallback import time); > 30 days → stale warning |
| Multi-host reports | only findings matching the asset's ip/hostname are attributed (unless `--no-host-filter`) |

GMP automation (e.g. `gvm-tools`) is possible but intentionally not implemented: file import is
simpler, auditable and does not require exposing the GMP socket. If you add it, use only commands
documented for your installed gvm-tools version.

The files in `sample_data/synthetic/` and generated by `evaluation/synthetic.py` are **synthetic**
fixtures shaped after the documented structures. They are not scan results. Validate the importer with
a real export from your lab before relying on it.
